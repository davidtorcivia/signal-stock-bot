OpenRouter provider routing

When the base URL points at OpenRouter, pin which upstream provider serves the model. Useful when a model has wildly different latency between hosts (e.g. Cerebras ≪ slower general-purpose providers). Ignored by non-OpenRouter endpoints. If you set provider directly in "Extra request body" above, that wins — these fields are skipped to avoid double-setting.

Tried in order. Empty = default OpenRouter routing (price-based with latency tie-break). Provider names must match the slugs shown on the OpenRouter model page (case-sensitive).

When true, requests fail if none of the preferred providers can serve them — preventing silent fallback to a slow host. When false, OpenRouter falls back to other providers after the preferred list is exhausted. No effect when the preferred list is empty.

Optional. throughput picks the fastest-tokens-per- second provider, latency the lowest-time-to-first- token, price the cheapest. Combine with the preferred list to sort within it. Empty = no sort.

Emoji reactor

Cheap secondary LLM call on every group message that decides whether to react with an emoji (and which one). Runs in the background, never blocks command handling, never surfaces output. Per-context toggle on /admin/contexts/<id>.

Replaces (not merged with) the main extra body for reactor calls. Typical use: disable thinking / pick the cheap reasoning tier.

Skip messages shorter than this without an LLM call. 0 = no minimum.

Post-LLM brakes

The cooldowns above decide which messages get evaluated; these decide how many evaluations may become actual reactions. They run after the model has already picked an emoji, so they cap the aggregate even when every individual decision was defensible. Counted per (chat, bot) from in-memory history, which resets on restart. 0 disables each independently.

Drop a pick whose emoji was already used within the last N reactions in that chat. Stops one emoji becoming the model's house style, which is what makes reactions read as automatic rather than considered.

The model rates how much each message warranted its reaction; picks below this are dropped. Leave at 0 at first — scores are recorded either way, and the dashboard's score distribution tells you where to actually put the threshold. Self-scores cluster high, so guessing it cold sets it too low to matter.

Natural response

Lets the bot decide to reply to a group message even when not mentioned, quoted, or addressed by name — for open-ended questions the bot might know about, or obvious follow-ups to its own prior replies. Decision runs inside the reactor's existing LLM call (no extra cost). The writer model may still bail with no message after looking at the full context. Per-context opt-in lives on /admin/contexts/<id>.

Off by default. Per-context flag is required in addition to this switch. Requires the emoji reactor to be enabled.

Minimum time between spontaneous replies in the same group. Prevents runaway interjections. Mentions/quotes always bypass this.

Optional. Appended to the reactor system prompt only when the should_respond tool is exposed (per-context flag on, global flag on, cooldown clear).

Deep think

A separate (smarter, slower, more expensive) model exposed to the writer LLM as a deep_think(question, context) tool. The writer decides when to delegate hard sub-problems. Empty fields fall back to the corresponding LLM setting above, so typically you only need to set the model + max_tokens (and maybe api_key/base_url) to point at a different endpoint. Per-context opt-out lives on /admin/contexts/<id>.

Replaces (not merged with) main extra_body. Typical use: enable high-effort reasoning on the deep model.

Hard cap on the optional context arg the writer passes. Truncated server-side — protects against runaway prompts.
